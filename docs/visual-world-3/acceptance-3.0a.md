# Visual World 3.0A — Graphics foundation: acceptance

Branch `feature/visual-world-3a`, from `origin/main` @ `8d25d5a`. Phase 4.5 (PR #13) was merged and green before
work started. Scope: 3.0A only. 3.0B and 3.0C have not been started.

## 1. Rendering approach

**Offline 3D → isometric sprite atlases, drawn by the existing PixiJS 8 renderer (options C + D of the audit).**
Buildings, trees, props and road tiles are modelled procedurally in code with Three.js and rendered offline in
headless Chromium with the game's exact projection, with PBR materials, soft shadows, glass reflections and GTAO
ambient occlusion. Pixi draws them as batched sprites, with runtime layers for time of day, night glow and ground
shadows. The full audit is in `rendering-architecture.md`.

**Justification.** This option gives the largest visual jump (real light, shadow and occlusion) at no runtime
cost, which was measured (§6). It keeps every gameplay system, hit test and e2e flow intact, and it doesn't need
a 2D artist: a model change re-bakes in about 3 seconds. A real-time 3D engine was not adopted. It would have
meant rewriting picking, depth sorting, Life Mode and the browser tests, with no visual gain at this fixed
isometric camera. Three.js is a devDependency of the bake only.

## 5. Visual quality evaluation

**Concrete improvements (seen in the shots):**

- Shot 2 vs before: buildings now read as solid volumes. Lit south faces and shaded east faces, occlusion under
  eaves and balconies, recessed windows with frames and sills, and roofs with thickness, overhangs, ridge caps and
  courses. Before, they were flat polygons with painted windows.
- Shot 3: the apartment block has scale and residential life (balconies, fins, café awning, roof garden); the park
  has paths, a fountain and mixed trees; townhouses read as individual houses with shops.
- Shots 1, 4, 5: every lot is a garden (pools, patios, hedges, trees). Streets have sidewalks, crossings, lamps
  and street trees. The terrain reads as meadow, not a grid.
- Shot 10: night has warm amber windows (not blown-out white), lit shopfronts and lamp pools on a readable
  moonlit base.
- Shots 11 and 14: residents and the player walk the new sidewalks and pass behind and in front of buildings
  and trees with correct occlusion. Shot 15: the selection outline sits exactly on the lot plate, showing that
  footprints and anchors line up.
- Shot 12: the placement ghost is the actual model, so the player sees what will be built.

**Remaining defects and shortcomings (honest list):**

1. **Mixed styles until 3.0B:** clubhouse, pool, mall, office and duplex still use 2.0 vector art. They stand out
   in the sample city (shot 4: the clubhouse).
2. **Procedural, not hand-crafted:** the models are clean and consistent, but their detail density and charm are
   below a commercial art team's hand-modelled assets (fewer bespoke props, no texture painting, simple
   materials).
3. **Characters unchanged:** residents and the player keep the 2.0 look and are small relative to the new
   buildings. That is 3.0C scope.
4. **Night is good, not cinematic:** no light spill onto the ground from windows, and lamp pools are simple
   ellipses. That is also 3.0C scope.
5. **Lot plates:** baked lawns are slightly brighter than the wild terrain, so lot boundaries are visible.
   Intentional (kept gardens), but the edge could be softened.
6. **Villa hip roof plus front gable:** where the bay gable meets the hip roof the junction is simplified.
7. **Fixed light direction:** baked shading doesn't rotate with the time of day. Only tint, shadow strength and
   glow change.
8. **Text:** shop signs carry abstract gold bars, deliberately. There's no generated lettering.

Verdict: the vertical slice looks substantially more polished than Visual World 2.0 in the running game. That
conclusion comes from the side-by-side shots above, not from the tests.

## 6. Performance (measured)

`node scripts/vw3_benchmark.mjs <url> [--uncapped] [--software] [--viewport=WxH]`. Production builds of `main`
(before) and this branch (after). Reference machine: Apple M2, macOS 26, Playwright Chromium; GPU runs use ANGLE
Metal. Raw data: `benchmark-3.0a.json`.

**Vsync on, 1440×900 (what a player sees):** every scenario holds **60 fps, p95 16.7 ms, p99 16.8 ms**, before
and after, including 300 residents commuting zoomed out.

**Uncapped (vsync off), 2560×1440:** real per-frame cost.

| Scenario | Before avg / p95 / p99 ms (fps) | After avg / p95 / p99 ms (fps) |
|---|---|---|
| Slice, gameplay zoom | 2.62 / 2.9 / 3.9 (381) | 2.61 / 3.0 / 3.9 (384) |
| Slice, close zoom | 2.42 / 3.7 / 3.8 (414) | 2.46 / 3.6 / 3.8 (407) |
| Sample city | 2.57 / 2.8 / 3.8 (389) | 2.57 / 2.9 / 3.8 (390) |
| 300 residents commuting, zoomed out | 3.84 / 7.7 / 9.1 (261) | 3.76 / 7.3 / 8.2 (266) |

**Software rendering (SwiftShader, 1440×900, worst-case proxy for weak GPUs):** both versions are fill-rate
bound. Before: 17.1–22.5 fps. After: 14.4–21.5 fps. The close-zoom slice drops from 17.1 to 14.4 fps because of
larger textured sprites plus the shadow layer. Neither version is smooth without a GPU.

**Other measurements:**
- Renderer CPU per frame (JS update): 0.02–0.05 ms without residents; 0.24 ms with 300 residents (0.49 ms before).
- Load: interactive about 0.4–0.6 s after navigation on both; atlases fully loaded about 0.5–0.7 s after
  navigation (vector art shows until then).
- Camera: a wheel zoom reaches the screen within two frames (about 32 ms at 60 Hz) before and after.
- Texture memory: atlases 26 MB (34.7 MB with mipmaps). The cached terrain texture is the same size as in 2.0.
  The ground texture now holds only flat decor, since roads became live sprites.
- Draw work: one textured quad per building, tree and road tile from four atlas pages; no per-frame geometry
  rebuilds.

## 7. Tests

| Suite | Result |
|---|---|
| Typecheck (`npm run typecheck`) | pass |
| Frontend unit (`npm test`) | 144 passed (133 before; +11 art pipeline and runtime tests) |
| Simulation (`npm run test:simulation`) | 286 passed |
| AI Architect (`npm run test:architect`) | 52 passed |
| API (`pytest`) | 66 passed |
| Security (`npm run security`) | 0 findings |
| Production build | pass |
| Playwright e2e (`npm run test:e2e`) | 42 passed (run twice locally, including after the final changes) |

New tests (`src/game/art/`): manifest validity against the simulation catalog; every frame exists in its atlas;
colour anchors are sane; every slice kind ships both facings and all 16 road masks; no building art rises above
`buildingLift + roofCapHeight` (hit testing); variant selection is deterministic and faces the street; non-baked
kinds and decor fall back to vector art; road masks; structural errors are reported, not thrown; the decor layer
uses baked sprites and shadows, rebuilds without leaking, and falls back per item and without a library.

Changed tests (interface extensions, not weakened): `worldVisuals.test.ts` expects the new `sun` field in
`WorldLighting`, and treats curbside street trees like lamps (allowed on road curbs, outside the walking lanes,
via `CURB_DECOR`).

These tests caught one real bug during development: street trees were mapped under the wrong key and silently
fell back to vector art.
