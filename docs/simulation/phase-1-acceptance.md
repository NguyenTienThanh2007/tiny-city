# Phase 1 final acceptance audit

Audit baseline: fetched `main` at `a019d29`, on the isolated `codex/phase-1-final-acceptance` branch. The Phase 1A engine and Phase 1B catalog/tools were retained. Simulation remains the authoritative, deterministic, framework-independent source of city state. No AI, pathfinding, new graphics system, or unrelated phase is included.

## Findings and disposition

Severity: P1 blocks a supported workflow; P2 causes incorrect behavior, missing feedback, or recovery risk; P3 is a nonblocking limitation. No P0 data-loss blocker was reproduced.

## Validation and reproduction

Local results: 155 simulation tests, 55 frontend tests, 16 Chromium gameplay tests, and 3 API tests passed. TypeScript checks (including browser tests/configuration), the simulation build and the production frontend build passed. The bundle-size advisory is listed as A14 above.

```sh
npm ci
npm run typecheck
npm run test:simulation
npm test
npm run build
npx playwright install chromium
npm run test:e2e
cd apps/api
uv sync --locked --extra dev
uv run --locked --extra dev python -m pytest -q -W error
```

`e2e/city-builder.spec.ts` runs against the real production Vite/Pixi frontend via `vite preview`, with the application's normal React StrictMode bootstrap. Browser contexts use isolated, deterministic fixtures; tests never replace Pixi with a mock or invoke editor callbacks directly. Pointer positions are derived from the public camera footprint, allowing zoom/pan/resize tests to verify the actual input transform. Browser assertions inspect displayed information and saved world data. Failed runs retain screenshots and traces. GitHub Actions runs the frontend/simulation, API, and Chromium gameplay jobs independently and uploads failure artifacts for seven days.

Public changes are additive: all catalog keys in `CONSTRUCTION_COSTS`, optional `LoadedCity.notice`, and optional viewport camera/gesture callbacks. World schema 2, CityCommand and SimulationEvent payloads, original storage key, prices and footprints remain compatible.

## Phase 2 handoff boundaries

- No unresolved reproducible P1/P2 issue remains within the covered Phase 1 workflows. Browser automation currently covers Chromium; other browser/GPU implementations have not received the same automated matrix.
- Road removal may disconnect buildings; the inspector now reports actual adjacency. Existing authored sample homes are grandfathered. No pathfinding or connected-to-a-particular-network rule is implied.
- Moving is free and preserves building IDs and references. Demolition gives no refund and rejects citizen-referenced buildings. History affects city data and funds while time/RNG progress; IDs are not reused after an abandoned edit.
- Legacy saves lack historical spending, so migration uses current funds as the opening balance. Recovery of corrupt simulation data explicitly warns that the ledger/clock history could not be restored.
- Pending queued commands remain runner state outside serialization. Phase 2 consumers must drain or journal them before saving; the current builder uses immediate atomic batches.
- The phrase parser remains a local demo. Browser persistence is local to this device/origin; FastAPI still exposes only the Phase 0 health/OpenAPI scaffold.
